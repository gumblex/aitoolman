# aitoolman - 可控、透明的LLM中间件

## 项目介绍
aitoolman 是一个面向开发者的LLM（大语言模型）中间件，旨在解决现有原厂SDK**供应商锁定**，应用框架的**流程不清晰、调试困难**等痛点。本库统一了流式、批次推理接口，集中管理多模型或多提供商，提供了简便的提示词模板与后处理管线，帮助开发者快速构建稳定、可调试的LLM应用。

## 设计理念
1. **用户完全控制**：所有提示词、数据流、控制流均由用户代码主导，LLM 作为执行工具，严格遵循预设指令，**无意外操作、无隐藏提示词和业务逻辑**
2. **流程透明可调试**：所有发往 LLM 和从 LLM 返回的数据均可自定义、可审计，便于排查问题和优化提示词
3. **供应商无关**：通过抽象层统一适配多种 LLM 提供商，轻松切换模型且充分利用各提供商的特色功能
4. **模块化设计**：组件职责单一，易于测试、替换和复用
5. **部署友好**：内置资源管理、错误处理，并提供微服务/HTTP 集成、监控审计能力，可直接用于生产环境

| 维度     | 原生 LLM SDK | aitoolman            | 完整 Agent 框架       |
|--------|------------|----------------------|-------------------|
| LLM角色  | 应用代码直接调用   | LLM 是工具人，仅执行预设指令     | LLM 是智能体，可自主决策    |
| 控制权    | 应用代码自行管理   | 用户完全控制流程             | 框架隐含控制流           |
| 提示词    | 应用代码拼装     | 开发者编写所有提示词，完全自定义     | 自带大量默认提示词         |
| 多模型适配  | 需按厂商分别适配   | 原生多提供商抽象与模型路由        | 多为单一平台或插件式适配      |
| 功能边界   | 仅底层 API    | 提供商抽象、应用层、简明编排       | 内置向量索引、RAG、规划、记忆等 |
| 适用场景   | 简单 API 调用  | 统一接入、模板化调用、模型路由、按需编排 | 开放式自主智能体、探索性应用    |

## 核心功能
- **多提供商统一抽象**：统一数据模型与各提供商格式策略，提供流批一体的推理接口，以及跨厂商的重试与取消。
- **应用层抽象**：模块化配置、Jinja2 提示词模板、统一模块结果、后处理与审计事件。
- **模型路由**：通过标签分组模型，支持多标签匹配、权重计算、输入 Token 超限过滤与候选降级。
- **流式处理**：流式输出、推理内容、XML 标签分发与通道解复用。
- **简明编排**：任务链、并发上限、停止控制与工具调用后跳转。
- **部署与集成**：CLI、OpenAI 兼容 HTTP 服务、ZeroMQ 微服务与监控审计，用于部署与集成。

## 适用场景
aitoolman 适用于以下场景：

- **文本处理管线**：结合提示词模板与后处理管线，构建分类、摘要、翻译、结构化提取等稳定处理流程。
- **配置统一管理**：集中管理多个模型与提供商的 API 密钥、模型参数与提供商设置。
- **模型路由与降级**：按标签与优先级选择模型，失败时自动降级，平衡成本、速度与效果。
- **任务编排**：支持串行与并行的 LLM 任务，配合并发上限与停止控制。

## 架构概览
1. 用户应用层：业务逻辑实现
2. 应用层 (LLMApplication / LLMWorkflow)：模块配置、模板渲染、结果处理、简明编排
3. 传输层 (LLMClient / Channel)：请求发送、流式响应传输、微服务通信
4. 数据接口层 (ProviderManager)：多厂商适配、请求调度、限流重试、模型路由
5. LLM 提供商 API (OpenAI / Anthropic 等)：底层 LLM 服务

## 快速开始
1. `pip install aitoolman`
2. 参考《[开发者文档](quick_start.md)》查看详细框架文档、API说明和示例代码
3. [配置](config.md) LLM提供商API密钥和模型参数 (llm_provider.toml)
4. 编写提示词模板配置 (app_prompt.toml)
5. 通过 LLMApplication 构建应用逻辑；需要串行或并行任务链时使用 LLMWorkflow

## 最佳实践

### 提示词设计
用试卷中的“**简答题**”（案例分析题）的格式设计提示词。格式：

1. **阅读材料**，需要分析的大段文字，或提供参考资料，历史对话上下文
2. **问题背景**，阐述场景设计和主要目标，是简答题的题干
3. **任务说明**，清晰指出需要做什么，是简答题的一个小问
4. **具体要求**，列出需要遵循的规则、方法和要点，是题型设计、得分点和括号中的提示
5. 可选的**输出范例**，直接用要输出的格式编写

提示词设计的原则：
- **专注单个任务**：一次只让AI处理一个任务或一组数据
- **首尾衔接**：提示词的结尾要和AI的答案开头能自然连贯；简短（一两行）的输入内容，可以放在提示词的最后
- **语言一致**：用主要工作语言编写提示词，目标语言的文本放在最后
- **简洁清晰**：用词简洁，尽量多写“要做什么”，少写“不要做什么”；避免让大模型看到无关内容
- **输出格式明确**：指定清晰的输出格式（如JSON、XML、Markdown）并给出示例

### 模块设计

- **模板变量**：使用 `{{ variable }}` 和其他 Jinja2 模板语法
- **上下文控制**：尽量少用上下文消息，优先优化提示词质量
- **模块化设计**：将复杂提示拆分为多个模块、全局模板，每个模块职责单一
- **流程优先**：避免让大模型执行确定性的任务，或仅用提示词限制大模型行为
- **工具描述**：为工具提供清晰、具体的描述和参数说明；不提供无用工具
